# ImamAli110 — معماری تولید و انتشار روزانه

## مسیر تولید

1. `app/llm_provider.py` زنجیرهٔ تأمین‌کننده را تعیین می‌کند: Groq رایگان، سپس هر درگاه سازگار با OpenAI، و در پایان Ollama محلی. شکست یا rate limit در یک لایه فقط به لایهٔ بعدی واگذار می‌شود.
2. `app/spiritual_content.py` متن را مرحله‌ای می‌سازد: یک درخواست کوچک برای نقشهٔ محتوا (عنوان، توضیح، برچسب‌ها، شش سرفصل) و سپس یک درخواست محدود برای هر بخش با سهمیهٔ واژگانی خودش. هر بخش پس از تولید سنجیده می‌شود؛ بخش کوتاه گسترش و بخش بلند کوتاه می‌شود، جمله‌های تکراری بازنویسی می‌شوند و در پایان متن مونتاژشده از دروازه‌های کیفیت می‌گذرد. دلیل این تقسیم، شکست مدل‌های کوچک رایگان در تولید یک JSON هشتصدواژه‌ای در یک نوبت است.
3. `app/spiritual_tts.py` فقط از صدای ثابت `fa-IR-FaridNeural` استفاده می‌کند. رویدادهای WordBoundary Edge TTS به cueهای SRT کوتاه تبدیل می‌شوند؛ اگر metadata یا فایل صوتی ناقص باشد چرخه متوقف می‌شود.
4. `app/spiritual_video.py` تا پنج جست‌وجوی Pexels انجام می‌دهد، کلیپ‌های متنوع را هر حدود ۱۸ ثانیه عوض می‌کند، موسیقی محیطی اصیل می‌سازد و زیرنویس فارسی را با FFmpeg روی تصویر می‌سوزاند. درخواست‌های Pexels با exponential backoff محدود retry می‌شوند؛ پس از خطای نهایی، کلیپ‌های مجاز `assets/fallback_videos/` استفاده می‌شوند و اگر پوشه خالی باشد، background انتزاعی تولید می‌شود، نه ادعای تصویر واقعی.
5. `app/spiritual_pipeline.py` thumbnail، توضیحات و فصل‌های ویدئو را می‌سازد؛ سپس با OAuth موجود و YouTube Data API برای slot امن بعدیِ ساعت ۱۸:۰۰ `Asia/Tehran` بارگذاری زمان‌بندی‌شده می‌کند.
6. تاریخچهٔ ۹۰ ویدئوی اخیر و شناسه‌های پاسخ‌گرفته در `state/` قرار می‌گیرند و با GitHub Actions cache بین اجراهای روزانه نگه‌داری می‌شوند. گزارش stage-by-stage با redaction اسرار در `logs/daily-<run-id>.log` و خروجی‌ها به‌مدت سه روز به‌عنوان artifact ذخیره می‌شوند.
7. پس از آپلود حداکثر سه نظر روشن و کم‌خطر پاسخ می‌گیرند. حداکثر ۵ ویدئوی اخیر بررسی می‌شود؛ نظرات مشکوک، حساس یا نامطمئن بی‌پاسخ می‌مانند.

## ساعت اجرا و انتشار

GitHub Actions روزانه برای ساعت ۱۴:۳۰ UTC (۱۸:۰۰ تهران) تنظیم شده است. هر اجرا پس از انتشار slot امروز، ویدئوی نوبت بعد را می‌سازد و برای ۱۸:۰۰ روز بعد زمان‌بندی می‌کند؛ اجرای نخست، یک روز warm-up دارد. کد slot را نزدیک پایان محاسبه می‌کند: اگر بیش از ۳۰ دقیقه تا slot همان روز مانده باشد همان slot، وگرنه slot روز بعد انتخاب می‌شود. GitHub schedule تضمین real-time ندارد؛ اگر شروع delayed شود، انتشار فوری اتفاق نمی‌افتد.

اجرای دستی `workflow_dispatch` به‌طور پیش‌فرض فقط پیش‌نمایش می‌سازد. انتشار دستی فقط با انتخاب صریح `publish=true` انجام می‌شود. اجرای زمان‌بندی‌شده پس از عبور از preflight OAuth، به‌صورت خودکار منتشر/زمان‌بندی می‌کند.

## پیش‌نیازها و fallback

**اجباری برای انتشار:** `YOUTUBE_CLIENT_ID`، `YOUTUBE_CLIENT_SECRET` و `YOUTUBE_REFRESH_TOKEN` در GitHub Actions Secrets. OAuth پیش از رندر بررسی می‌شود. هر خطای auth مانع ساخت یا آپلود می‌شود.

**اختیاری:** `GROQ_API_KEY` برای inference طرح رایگان، `LLM_BASE_URL`/`LLM_API_KEY`/`LLM_MODEL` برای هر درگاه سازگار با OpenAI، و `PEXELS_API_KEY` برای stock footage. workflow حتی با Groq key مدل محلی `qwen2.5:3b` را آماده نگه می‌دارد تا هنگام rate limit یا outage fallback داشته باشد. بدون Pexels، تصاویر انتزاعی تولید می‌شوند. هیچ سرویس پولی لازم نیست، اما نرخ/دسترسی طرح‌های رایگان و GitHub Actions تضمین دائمی ندارند.

## حواجز الجودة

- متن زیر ۶۵۰ یا بالای ۹۰۰ واژه، خروجی JSON معیوب، عنوان تکراری یا محتوای دارای وعدهٔ درمان/ثروت قطعی رد می‌شود.
- نقل‌قول/آیه/حدیث منسوب به منبع ناشناخته تولید نمی‌شود؛ خطاهای LLM یک‌بار برای اصلاح ساختار بازتولید می‌شوند و سپس fail-closed است.
- صدای fallback به گویندهٔ دیگری تغییر نمی‌کند؛ اگر Edge TTS در دسترس نباشد، این اجرای تولید متوقف می‌شود.
- اگر FFmpeg، کپشن، thumbnail یا فایل MP4 ناقص باشد، هیچ uploadی شروع نمی‌شود.
- ویدئو فقط وقتی موفق محسوب می‌شود که API شناسهٔ ویدئو و زمان انتشار را بازگرداند. OAuth، API key، توکن یا محتوای Secret در log نوشته نمی‌شود.
- تاریخچهٔ تکرار بر GitHub Actions cache متکی است؛ پاک‌شدن cache می‌تواند تکرار موضوع را ممکن کند، هرچند بقیهٔ quality gates فعال می‌مانند.

## وضعیت فایل‌های قبلی

Workflowهای قدیمی خبر، Colab/Kaggle و پایش شش‌ساعته از شاخهٔ فعال حذف شده‌اند. برخی ماژول‌ها و تست‌های اخبار فقط برای سازگاری تاریخی باقی مانده‌اند؛ workflow جدید هیچ‌یک از آن‌ها را اجرا نمی‌کند. workflow دستی OAuth بدون انتشار حفظ شده است.
