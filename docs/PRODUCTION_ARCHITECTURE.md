# ImamAli110 — معماری تولید و انتشار روزانهٔ Shorts

## مسیر فعال تولید

1. فرمت فعال در `config/channel.yaml` برابر `content.production_format: shorts` است. `app/spiritual_pipeline.py` بر اساس این گزینه، تولید Shorts یا خط قدیمیِ ویدئوهای بلند را انتخاب می‌کند.
2. `app/spiritual_shorts.py` متن فارسی ۳۶ تا ۴۸ واژه‌ای را با چهار beat می‌سازد: هوک فوری، همدلی آرام، یک اقدام کوچک، پایان امیدوارکننده. متن باید hook پرسشی کوتاه، نگارش مناسب مکث، عنوان تازه، و چهار جست‌وجوی تصویری متمایز داشته باشد. متن گفتار هر scene باید دقیقاً با script برابر باشد؛ متن تکراری، مقدمهٔ کند، اجرای نامتناسب و خروجی ناقص fail می‌شوند.
3. مدل‌ها از همان زنجیرهٔ قابل‌پیکربندی عبور می‌کنند: Groq در صورت تنظیم، سپس gateway سازگار با OpenAI، و در پایان Ollama. شکست همهٔ مدل‌ها یا ردشدن هر شرط کیفی اجرای تولید را متوقف می‌کند.
4. `app/spiritual_tts.py` صدای ثابت فارسی را جداگانه برای چهار beat می‌سازد و سرعت/زیر‌وبمی را کمی تغییر می‌دهد: هوک پرانرژی‌تر، میانه آرام‌تر، بخش سوم اطمینان‌بخش و پایان انگیزشی‌تر. مکث کوتاه میان sceneها و captionهای دقیق از WordBoundary ساخته می‌شوند؛ صدای جایگزین یا caption تقریبی مجاز نیست.
5. `app/spiritual_video.py` برای هر beat یک درخواست Pexels با پرس‌وجوی همان صحنه انجام می‌دهد و فقط فایل عمودی را می‌پذیرد. چهار segment با زمان‌بندی گفتار همگام می‌شوند. اگر حتی یک کلیپ مناسب، اعتبار API یا دارایی تصویری عمودی حاضر نباشد، رندر Shorts عمداً متوقف می‌شود؛ فریم انتزاعی یا b-roll عمومی مسیر جایگزین نیست.
6. برای Shorts خروجی 720×1280، هوک درشت در ناحیهٔ امن، زیرنویس ASS خوانا و SRT جانبی، موسیقی چهارمرحله‌ایِ هماهنگ با کات‌ها، sidechain ducking زیر گوینده، fade و کاور فارسی ساخته می‌شود. موسیقی مجاز داخل `assets/music/` در صورت وجود استفاده می‌شود؛ در غیر این صورت bed آرامِ procedural ساخته می‌شود.
7. `app/media_qa.py` پیش از آپلود بررسی می‌کند: وجود فایل‌ها، ابعاد واقعی thumbnail، نسبت 9:16 و حداقل 720×1280، مدت ۱۵ تا ۴۰ ثانیه، اندازه و تعداد captionها، وجود فایل زیرنویس سوخته‌شده، hook overlay، چهار صحنهٔ تصویری متصل به جست‌وجوهای متمایز، منبع عمودی تأییدشده و ducking موسیقی. هر خطا upload را می‌بندد.
8. پس از عبور QA، خط موجود از YouTube OAuth، زمان‌بندی ۱۸:۰۰ تهران، ثبت تاریخچهٔ موضوع/شناسه و مدیریت محدود و ایمن نظرها استفاده می‌کند. dry-run/آپلود خصوصی workflow دستی همچنان جداست؛ این تغییر هیچ ویدئوی فعلی را منتشر نمی‌کند.

## پیش‌نیازها و زمان‌بندی

- `daily_run.yml` روزانه ساعت ۱۴:۳۰ UTC اجرا می‌شود و پس از preflight OAuth، در صورت عبور همهٔ gateها Short را برای ساعت ۱۸:۰۰ تهران زمان‌بندی می‌کند. GitHub Actions best-effort است و زمان شروع دقیق تضمین نمی‌شود.
- برای اجرای خودکار Shorts به secrets موجود YouTube و `PEXELS_API_KEY` نیاز است. Pexels باید برای **هر چهار scene** ویدئوی عمودیِ قابل‌استفاده بدهد؛ در غیر این صورت خروجی منتشر نمی‌شود.
- مدل نوشتن متن می‌تواند از `GROQ_API_KEY`، تنظیمات درگاه عمومی سازگار با OpenAI، یا Ollama استفاده کند. Edge TTS به اینترنت نیاز دارد.
- اجرای محلیِ امن: `python scripts/daily_run.py --dry-run`. پیش‌نمایش دستی Actions پیش‌فرض آپلود ندارد؛ برای انتشار دستی باید ورودی `publish` صریحاً انتخاب شود.
- تاریخچهٔ کانال و دفتر پاسخ به نظرها در `state/` نگهداری می‌شود؛ artifactها و گزارش مرحله‌ای workflow سه روز در GitHub Actions می‌مانند.

## دامنه و محدودیت تضمین

کیفیت با قواعد قابل‌آزمونِ متن، قاب، زیرنویس، طول، صحنه‌ها و میکس کنترل می‌شود و خروجی ضعیف خودکار رد می‌شود. این قواعد تضمین وایرال‌شدن یا قضاوت انسانی دربارهٔ سلیقه و کیفیت هر کلیپ را نمی‌دهند. کد جست‌وجوی مستقل و همگامِ هر صحنه را ثبت می‌کند، ولی تطابق تصویریِ معناییِ واقعی را مدل بینایی جداگانه تشخیص نمی‌دهد. هیچ ویدئویی با این تغییر مستقیماً تولید یا منتشر نشده است؛ انتشار جدید فقط با اجرای workflow پس از ادغام این تغییر و عبور از preflight/QA امکان‌پذیر است.
