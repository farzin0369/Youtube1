# تولید خودکار با صدای خود صاحب کانال

## وضعیت فعلی و واقعیت فنی

خط تولید موجود دو مسیر TTS دارد: صدای عمومی فارسی Edge TTS و API سرویس ElevenLabs. فقط مسیر دوم می‌تواند از یک Voice ID ثبت‌شده/کلون‌شده استفاده کند؛ متغیر `ELEVENLABS_VOICE_ID` باید شناسهٔ صدایی باشد که خود صاحب کانال مجاز به استفاده از آن است. اضافه‌کردن این شناسه به‌تنهایی صدای شخص را ثبت یا کلون نمی‌کند.

برای جلوگیری از انتشار ناخواسته با صدای عمومی، قابلیت fail-closed اضافه شده است:

- در GitHub → Settings → Secrets and variables → Actions → Variables مقدار `REQUIRE_OWNER_VOICE=true` را بگذارید.
- مقدار `TTS_PROVIDER=elevenlabs` را به‌عنوان Repository Variable تنظیم کنید.
- `ELEVENLABS_API_KEY` را فقط به‌عنوان Repository Secret اضافه کنید.
- `ELEVENLABS_VOICE_ID` را به‌عنوان Repository Variable قرار دهید؛ این باید شناسهٔ صدای خودتان باشد که در حساب سرویس ایجاد/ثبت کرده‌اید.
- اگر هرکدام تنظیم نباشد، pipeline با خطای روشن متوقف می‌شود و به صدای عمومی fallback نمی‌کند.

## هزینه و محدودیت

این پیاده‌سازی اتصال خودکار به صدای ثبت‌شده را فراهم می‌کند، اما API ElevenLabs ممکن است پولی یا سهمیه‌دار باشد. من در این تغییر هیچ کلید یا Voice ID فرضی قرار نداده‌ام و هیچ درخواست پولی اجرا نکرده‌ام. با تنظیم `REQUIRE_OWNER_VOICE=true` نمی‌توان ادعا کرد مسیر رایگان است؛ فقط تضمین می‌شود که در صورت نبود تنظیمات صدای صاحب کانال، خروجی با صدای عمومی ساخته نشود.

مدل‌های متن‌باز voice cloning باید جداگانه از نظر پشتیبانی واقعی فارسی، کیفیت، مجوز استفادهٔ تجاری در یوتیوب و منابع محاسباتی بررسی شوند. برای نمونه، XTTS-v2 در فهرست زبان‌های رسمی خود فارسی را ندارد و مجوز وزن‌های آن محدودیت غیرتجاری دارد؛ بنابراین به‌عنوان راه‌حل آمادهٔ این پروژه انتخاب نشده است.

## حفظ خودکارسازی

پس از یک‌بار ساخت/ثبت صدای شخص و تنظیم Secret/Variableها، تولید و زیرنویس‌گذاری از مسیر عادی GitHub Actions ادامه پیدا می‌کند؛ ضبط روزانه لازم نیست. اگر هنوز صدای کلون‌شده و معتبر در سرویس موجود نباشد، این مرحله نیازمند یک‌بار راه‌اندازی حساب/صدا است و نمی‌توان آن را از داخل مخزن یا بدون دسترسی به صدای مرجع، خودکار و کامل انجام داد.
